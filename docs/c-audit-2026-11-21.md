## Scope and language inventory

Reviewed public records and ownership contracts, `src/`, the private Speex wrapper
and allocator hooks, `adapters/hail.c`, concurrency and installed consumers,
qualification tools, native Win32 capture/caption/inference handoff, CMake and CI.
No DSP algorithm, numerical acceptance threshold or public structure changed.

The library already used C. Remaining first-party native implementations were
ported to C11: independent-session concurrency, installed-Hail concurrent consumer,
acoustic runner, rejected residual experiment, stage-order probe, acquisition/live
capture, Win32 captions, PCM file handling and application workers/UI. Default
projects now declare `LANGUAGES C`, require C11 and disable language extensions.
C11 atomics replace C++ atomics; Windows/POSIX helpers replace C++ threads.

Two deliberate C++ translation units remain:

- `tests/consumer/main.cpp`: optional foreign-C++ caller of the public C ABI.
  `BF_TEST_CXX_COMPAT=ON` explicitly enables it; CI retains this coverage.
- `tools/acoustic-runner/webrtc_bridge.cpp`: optional WebRTC 2.1 C++ API shim.
  The acoustic frontend and all Baffle processing remain C11; this comparison
  option explicitly enables C++ and never links WebRTC into the Baffle core.

Sherpa-onnx/ONNX Runtime are separately maintained C++ implementations behind a
C API. Static linkage does not turn them into C11. Python qualification scripts,
CMake and PowerShell automation remain external tools, not runtime dependencies.
A literal all-C11 speech inference stack has **not** been implemented.

## Confirmed findings and corrections

### CA-01 — Medium: retirement success was not established

The saved C++ acquisition/live helpers used cleanup that ignored pending/failed
`ha_stream_close_finish` and context destruction results. A successful processing
return could therefore obscure incomplete SDK retirement. This is a source-confirmed
error path, not evidence of a reproduced physical-device shutdown race.

[Checked retirement](../tools/acoustic-runner/hail_owner.h) now polls within an
explicit time/work bound, releases handles only on SDK success and preserves them
on timeout. Acquisition/live capture return failure (`2` for unproven retirement);
the native application makes that condition fatal to subsequent sessions. Core
DSP storage has no Hail callback aliases and is retired independently.

[Regression](../tools/acoustic-runner/retirement_test.c): actual public virtual
backend holds retirement; a zero-budget attempt must retain both handles and
report `HA_PENDING`. Clearing the fault permits a successful retry, null handles
and an idempotent final cleanup. Windows and Linux ARM64 each passed 1/1. No private Hail access.
A failed retirement can deliberately retain SDK resources until process exit;
that is safer than reclaiming aliased storage and is explicitly not recovery.

### CA-02 — Medium: flush evidence could imply an acknowledgement

The old acquisition tool initialized the reported flush result to `HA_OK`, including
runs that had not observed completion. That value alone did not establish an ACK.
[Acquisition](../tools/acoustic-runner/hail_acquire.c) now initializes a configured
cancellation to pending, records `flush_requested` and `flush_acknowledged`, and
sets the completion result only after the matching acknowledgement is observed.

[Executable regression](../tests/acoustic_tools.py) checks virtual stop/restart
cancellation and an uncancelled control. Capture continues without loss; requested
and acknowledged flags agree with the actual scenario; calibration stays null.
Running this regression against the saved C++ acquisition executable failed on
missing `flush_requested`; the corrected tool passes. This reproduces missing
evidence metadata, not an arbitrary hardware-delayed ACK. Queue invalidation,
backend ACK, presentation completion and acoustic silence remain distinct.

### CA-03 — Low: C-only default build required C++ through tests

Root/installed-consumer tests and tools previously enabled C++ for their owned
threading/frontend implementation. A C11 library build with tests therefore needed
a C++ compiler. [Root CMake](../CMakeLists.txt), [Hail consumer](../examples/hail-consumer/CMakeLists.txt)
and [acoustic CMake](../tools/acoustic-runner/CMakeLists.txt) now compile C sources;
C++ enablement is confined to the two explicit foreign compatibility cases above.

MSVC 19.44 requires `/experimental:c11atomics` for its C atomics header. The flag
is applied only to affected MSVC consumers/tests. ClangCL does not need it. The
native build helper selects ClangCL, consistent with Hail's existing lock-free
atomic requirements. The caption application checks relevant atomic operations
for lock freedom before permitting a session. No lock-free claim for arbitrary
toolchains/architectures follows.

## Memory, numerical and real-time review

- Public PCM validation bounds frames/channels/formats and timestamp arithmetic;
  byte-wise sample transfer avoids assuming external pointer alignment. Caller
  accessibility and disjoint-buffer obligations remain caller contracts.
- Arena queries bound geometry before products/alignment; SRC uses checked sizes,
  bounded taps, rational phase and explicit consumption/output capacity. No
  arbitrary caller-controlled `SIZE_MAX` reaches the private align helper.
- Core processing contains no heap, filesystem, networking, locks or worker waits.
  Speex allocation is admitted only through a thread-local initialization arena;
  initialization, reset/process ownership and deinit remain single-owner operations.
  Noalloc tests and symbol inspection exercise separate evidence categories.
- NS FFT sizes/hops/channels, AEC tails/channels, SRC taps/capacity and adapter
  history/pump budgets bound work. This is not a hard deadline guarantee on every
  supported maximum configuration. No fresh performance qualification is claimed.
- Invalid/nonfinite PCM is checked before adaptive processing; sanitization is
  explicit. Existing clipping, missing-reference, epoch, generation and recovery
  assertions remain unchanged. No AEC/NS/AGC parameter tuning was made.
- Win32 capture uses preallocated DSP/queue storage and an acquire/release SPSC
  handoff. Inference and UI own decoding/text locks; those locks never run in a
  device callback. Model allocation and file I/O are outside DSP processing.
- Native text/windows/history and token counts have fixed capacities. Actual
  thread completion is checked before reclaiming worker-owned application state.
  The caption/history regression checks the 64k bound and repeated paragraph trim.
- The native WAV parser rejects unsupported geometry, truncated/oversized RIFF
  chunks and nonfinite PCM transactionally. `--wave-test` checks 56 valid/malformed
  cases without microphones or models. Native comparison/report outputs use exclusive creation; existing offline QA
  commands retain their previous output-overwrite contracts.
